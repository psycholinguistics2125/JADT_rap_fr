# Deployment — JADT rap-fr comparison website

Live site: **https://compare-topic-model-jadt2026.fr**
Server: **`ubuntu@91.134.239.219`** (OVH VPS)
Stack: Docker Compose in `website_output/` — a `web` container (gunicorn → Dash on :8050)
behind a `caddy` container (auto-HTTPS via Let's Encrypt, ports 80/443).

`website_output/` is **not** in git and the server does **not** pull from git — the folder is
built locally and copied to the server.

---

## 1. Build the site locally

From the project root, with the venv `/home/robin/env/rap_fr`:

```bash
python build_website.py \
  --bertopic-folder results/BERTopic/run_20260706_220123_solon \
  --lda-folder      results/LDA/run_20260706_171018_both \
  --iramuteq-folder results/IRAMUTEQ/evaluation_20260126_124001 \
  --comparison-folder results/comparisons/comparison_20260706_222138 \
  --output-dir website_output
```

Swap the folder paths for whichever runs / comparison you want to publish.
Local preview before deploying: `cd website_output && python app.py` → http://localhost:8050

## 2. Copy the build to the server

Use **rsync** (in-place, only changed files). Do **not** use `scp -r website_output …:~/website_output`
on an update — it nests the folder inside itself (`~/website_output/website_output`).

```bash
rsync -av --delete \
  /home/robin/Code_repo/psycholinguistic2125/JADT_rap_fr/website_output/ \
  ubuntu@91.134.239.219:~/website_output/
```

(First-ever deploy used `scp -r website_output ubuntu@91.134.239.219:~/website_output`.)

## 3. Rebuild + restart on the server

```bash
ssh ubuntu@91.134.239.219
cd ~/website_output
```

The server has **docker-compose v1.29.2**, which crashes on recreate with
`KeyError: 'ContainerConfig'` (v1 is incompatible with the newer Docker image format).
Work around it by removing the old `web` container first (Caddy stays up):

```bash
docker-compose rm -sf web
docker-compose up --build -d
```

If it still fails, take the whole stack down and up (named volumes / TLS certs are preserved):

```bash
docker-compose down            # keeps caddy_data (certs); add -v ONLY to wipe volumes
docker-compose up --build -d
```

### Better: switch to Compose v2 (one-time, removes the bug)

```bash
sudo apt-get update && sudo apt-get install -y docker-compose-plugin
docker compose up --build -d   # note: "docker compose", no hyphen — use this from now on
```

## 4. Verify

```bash
docker-compose ps                 # or: docker compose ps
docker-compose logs --tail=30 web # expect gunicorn listening on 0.0.0.0:8050
curl -sI http://localhost:8050/ | head -1   # HTTP/1.1 200 OK
```
Then check the public URL: https://compare-topic-model-jadt2026.fr

## Notes / gotchas

- **Domain / TLS**: handled by Caddy (`Caddyfile` in `website_output/`) for
  `compare-topic-model-jadt2026.fr`. Needs DNS → `91.134.239.219` and ports 80/443 open.
  Certs live in the named volume `caddy_data`; never `docker-compose down -v` unless you want
  to re-issue them.
- **`web` has no public port** — only Caddy exposes 80/443 and reverse-proxies to `web:8050`.
  For a container test without Caddy, temporarily add `ports: ["8050:8050"]` to the `web` service.
- **Other OVH boxes** seen in history (not current): `152.228.243.49`, `188.165.71.47`.
- **Data lives in the build**: `website_output/data/site_data.json` (~17 MB) is generated by
  `build_website.py`; syncing `website_output/` is all that's needed — nothing else to copy.
